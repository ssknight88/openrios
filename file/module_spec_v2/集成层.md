# 集成层 · backend_top 接线依据

**本文档只回答一件事：每个模块 ⑥ 的 in-event，由哪个模块的 out-event 或 Static Info 供给。**

模块内部怎么算、判据是什么、为什么这么设计——**一律不在这里**，在各模块文档的 ①–⑥。
写 `backend_top` 时照 §1 的边表连线即可；连完之后照 §4 自查一遍闭合。

本层另有两件只有它看得见的事：§2 无主的定义（`ISQ_Payload` 装配这处胶水 + 跨级冻结的 schema）、
§3 跨模块才成立的约束（组合环、端口正交、采样口径相反）。

**术语**：**库内**指本目录下有微架构文档的模块；**库外**指 FE / 各 FU（含 G3 的 LSU）/
`g3_lsu_iface` / 顶层——它们没有文档，凡送往库外的边，传输语义由 §1.5 补齐。
`p3_arbiter_G0/G1` 模块本体不入库，但 schema 有文档，按库内处理。

**实例数**（backend_top 例化时用）：`ISQ_Group0..3` 各 1；`p1_ISQ_input_mux` ×4（每组一份）；
`FU_input_mux` ×9，但它是 `ISQ_Group` 的内部子块，**不在本表出现**；其余模块各 1。

### 1.2 P2 / P3 · 发射到完成

```text
ISQ_Group_g              → 组内被选中的 FU        整条 issue 交付（各组字段清单见其 ⑥）

lane 驱动方 ＝ lane0/1：p3_arbiter_G0/G1 的仲裁输出
              lane2：  FPU completion 直连（无仲裁器，仍按 completion_common 驱动）
              lane3：  g3_lsu_iface —— LSU 只交 tag/data/excp/cause/tval 五项，
                       由本模块展开成 completion_common 并把 mispredict_flag /
                       is_mret / fpu_fflags 接地（判据见 `../FU契约.md` §1.3）

lane 驱动方              → Buffer                tag_out（写地址）、Result_valid、result_data
lane 驱动方              → CompletionScoreboard  tag_out（寻址）、Result_valid、
                                                 exception_flag/cause/tval、
                                                 mispredict_flag/target_pc、is_mret、fpu_fflags
lane 驱动方              → ISQ_Group_g           bypass_valid[b]、bypass_tag[b]、bypass_data[b]
                                                 （4 lane，四组全收）
lane 驱动方              → dependency_check      bypass_valid[b]、bypass_tag[b]（不含 data）
lane 驱动方              → §2.1 装配             bypass_data[b]

p3_arbiter_G0 的 lane 0  → system_instruction_handler
                                                 Result_valid[0]、tag_out[0]、csr_sideband
                                                 （is_csr、csr_write_enable、csr_addr、csr_wdata）
csr_fu                   → system_instruction_handler   csr_addr（读地址）
system_instruction_handler → csr_fu              CSR[csr_addr] 旧值、current_priv、fs_enabled
```

- **`system_instruction_handler → FPU  frm` 这条边不存在**：舍入模式已在派遣拍定格成
  `effective_rm` 进了 ISQ_G2 的 payload，FPU 直接用，不读实时 `frm`。
  接线时不要"顺手"把它连上——那会让 entry 驻留多拍后取到变过的值
- `fs_enabled` 送 csr_fu 是为了 `FS == Off` 时把 `fcsr` / `fflags` / `frm` 三个地址判为非法：
  **必须报异常，不能只清 `csr_write_enable`**——只清写使能会让这条非法 CSR 指令
  被当成一次普通完成，正常退休

- **一次 writeback 落两个地方**：`result_data` 进 `Buffer`，`exec_done` 与事件批进 `CompletionScoreboard`
- **lane 0 的 `csr_sideband` 绕过 SCB**，直连 `system_instruction_handler`——全库唯一一条
- **恒零字段由 FU 驱动、仲裁器不补造**：G2/G3 直连、没有仲裁器可以代置 0，
  统一到 FU 侧四条 lane 的输入契约才是同一份

## 2. 无主的定义

**胶水 = 没有主人的组合逻辑**：它把若干模块的输出组合起来喂给另一些模块，而其输出
**不是任何模块的 out-event**。判定：先看有没有模块在 out-event 里认领——有主就归那个模块。
附加条件：胶水**不持有状态**。

全库只有一处胶水：`ISQ_Payload` 装配。
（`isq_wr_en[g]` 虽也是跨模块组合，但已由 `dispatch_logic` 在其 out-event 认领，不算。）

### 2.1 `ISQ_Payload` 装配

两个候选 slot 各装配一份完整 payload，供 4 个 `p1_ISQ_input_mux` 二选一。
**本节是 `ISQ_Payload` 的唯一 schema 定义处**——四个 `ISQ_Group` 各自只捕获其中一个子集。

**源数据选择**：对每个 `(slot s, source x)`，按 `dependency_check` 给的 onehot0 选择码
`rs_data_sel_t[s][x] = {sel_arf, sel_commit, sel_bypass}` 取值：

```text
sel_arf       → rsX_is_fp[s] ? FP_ARF[fp_read_idx[x]] : INT_ARF[rsX_idx[s]]
sel_commit[c] → commit_data[c]
sel_bypass[b] → bypass_data[b]
全零          → rsX_data[s][x] = 0（本拍不采样该源）
```

本层**不做任何 busy / tag 比较**——选择码由 `dependency_check` 唯一生成，
`sel_commit` 与 `sel_bypass` 的优先级也在那里实现。
`rs3` 永不选 `INT_ARF`（上游契约 `use_rs3[s] ⇒ rs3_is_fp[s]`），故 §1.1 里 `INT_ARF`
只登记 `rs1/2_idx` 的 4 个读口。
`fp_read_idx[x]` 没有 slot 维度而选择按 `(s,x)` 做——两者的自洽性论证见
`FP_read_address_mux微架构文档.md` ④，本层不重复。

**schema（字段 → 来源）**：

```text
rs1_data / rs2_data / rs3_data                                本节选出
rs1_ready / rs2_ready / rs3_ready                             dependency_check
rs1_wait_tag / rs2_wait_tag / rs3_wait_tag                    dependency_check
self_tag                                                      dependency_check
FU_Group(2)                                                   dispatch_logic
imm_valid / imm_data                                          IB
pc / inst_bits / is_compressed / pred_taken / pred_target_pc   IB
is_store / mem_funct3 / rd_is_fp                              IB
exe_subop[23:0] / full_decode[16:0]                           IB
```

**唯一一处装配侧覆写**：`full_decode` 的 `rm[2:0]` 三位由 `dispatch_logic` 的
`effective_rm[s]` 覆盖后再进 payload，其余 **14** 位（`[16]` / `[15]` / `[11:0]`）原样取自 IB。
`effective_rm = (rm == DYN) ? frm : rm` 在派遣拍定格，只有 G2 消费。
覆写的理由（快照优于让 FPU 读实时 `frm`）见 `dispatch_logic微架构文档.md` ④#1。

**不进 payload 的**：`slot_ISQGroup`（已译码成 `select_payload`，mux 实例本身即代表目标组）；
`rd_idx` / `use_rd` / `rd_write_enable`（回写按 `tag_out` 寻址，目的寄存器信息在 alloc 拍
已进 SCB，FU 不需要）。`rd_is_fp` 是例外——它进 payload，只为 G3 区分同宽度的整数与 FP load。

### 2.2 跨级冻结的 schema

以下字段跨 Decode → IB → ISQ → FU 四级传递，四级必须认同一份布局，却没有任何一级拥有它的
定义——判据同 §2.1，故归本层。**只冻结宽度与编码，不规定 packed 字段顺序。**

```text
IB_Payload   总逻辑宽度 302 bit
ISQ_Payload  总逻辑宽度 486 bit

exe_subop[23:0]    = {format[1:0], opcode_or_op[6:0], funct3[2:0], high_fixed[11:0]}
                     format = 01 普通 32-bit 编码；10 = RVC
                     FP 的 .S/.D 精度由高位固定段区分，不另设 fmt 字段
full_decode[16]    = csr_write_intent
full_decode[15]    = illegal
full_decode[14:12] = rm[2:0]
full_decode[11:0]  = csr_addr[11:0]

rm 编码   000/001/010/011/100 = RNE / RTZ / RDN / RUP / RMM
          111 = DYN（FPU 在 issue 时取 SIH 的 frm）
          101/110 保留
```

- `illegal = 1` 时 `exe_subop` 取兜底值，dispatch 固定送 G0 的 ILLEGAL 完成路径；
  其 `tval` 由 `inst_bits` 提供
- `rm` / `csr_addr` / `csr_write_intent` 是 Full Decode 控制字段，不编码进 `exe_subop`；
  不适用时置零忽略
- **`csr_write_intent` 不可由后端推导，必须由 decode 按指令编码语义产生**：
  register-form 的 `CSRRS` / `CSRRC` 是否真写 CSR，取决于 **`rs1_idx == x0` 这个寄存器号**，
  **不是 `rs1_data == 0` 这个值**。而 `rs1_idx` 不进 ISQ payload（payload 只带 `rs1_data`），
  所以这一位是后端**唯一拿不到的**判据。立即数型看 `uimm == 0`，那个可以从 `imm_data` 判，
  但两种形式共用一位更简单。
  少了它有两处会错：① `csrrs t0, fcsr, x0` 是纯读，被当成写会让 apply 路径置 `FS ← Dirty`
  （而"CSR 读不置脏"是既定口径）；② 只读 CSR 的**读合法、写非法**，分不开就只能一刀切
- `rm` 保留值与 `FS == Off` 的非法检查责任**不在本层**，也不在 G2——由 `dispatch_logic`
  读 SIH 的 `fs_enabled` / `frm` 合成 `fp_illegal`，命中即改道 G0 的 ILLEGAL 路径。
  裁定见 `../walkthrough.md` §1.22
- `FU_Group` 在 ISQ 聚合中为 2 bit（G1 只用 `0/1`，G2/G3 不消费）；
  Decode → IB **不携带**它，由 dispatch 从 `exe_subop` 导出 `slot_FU_Group`

## 3. 连接的合法性

模块各自的 flush 响应、采样约定、同格写口次序都在各自 ③，本层不重复。
接线时逐条核这几项：

- **demux**：同一起点的 event 无交集
- **fan-out**：单向非握手
- **mux**：同一终点的 event 无交集
- `Buffer` 与 `CompletionScoreboard` 的 4 个 writeback 写口地址正交——四条 lane 属四个不同在飞 tag
- `INT_tag_mapping` 的 2 个 alloc 写口同格时，按其 ③ 的写口次序解决
- `FP_tag_mapping` 只有 1 个 alloc 写口 / 1 个清除口，由双FP阻塞保证一拍至多一笔

> 三条**故意不建**的边（建了就成组合环）、跨模块相反的采样口径、以及 flush 侧
> "判定归 SCB、翻译归 `flush_model`"的分工，都记在 `../walkthrough.md` §1.12–§1.14。
> 接线前先看那三条，免得"顺手"把不该连的连上。

## 4. 本层的核对清单

只有本层看得见全库的边集合，以下核对归本层：

- 每条 out-event 字段、每条 Static Info **是否真有消费者**（模块文档不写消费者）

  本表中属于此类的：`trap_vector(cause, is_interrupt)`、`CSR[csr_addr]`、
